Проект: Крестики-нолики с авторизацией

Это backend-приложение для игры в крестики-нолики. Проект продолжает предыдущую версию игры и добавляет базу данных, пользователей, авторизацию и возможность играть не только против компьютера, но и против другого игрока.

Приложение построено по слоям:

- web — HTTP-запросы, контроллеры и модели для API;
- domain — основная логика игры и пользователей;
- datasource — работа с PostgreSQL через SQLAlchemy;
- di — настройка зависимостей.

Что нужно реализовать

В проект нужно добавить PostgreSQL вместо хранения данных в памяти. Игры и пользователи должны сохраняться в базе данных через SQLAlchemy.

Также нужно добавить пользователей. У каждого пользователя есть UUID, логин и пароль. Пользователь может зарегистрироваться и авторизоваться через Basic Auth. Логин и пароль передаются в заголовке Authorization в формате base64(login:password).

Запросы регистрации и авторизации должны быть открытыми. Все остальные запросы должны требовать авторизацию. Если пользователь не авторизован или передал неверные данные, сервер должен вернуть 401 Unauthorized.

Игровую логику тоже нужно расширить. Теперь игра может быть:

- против компьютера;
- против другого пользователя.

У игры должны быть состояния:

- ожидание второго игрока;
- ход конкретного игрока;
- ничья;
- победа конкретного игрока.

Также нужно хранить, какими значками ходят игроки: X или O.

Основные возможности API

Приложение должно уметь:

- регистрировать пользователя;
- авторизовать пользователя;
- создавать новую игру;
- получать список доступных игр;
- присоединяться к игре;
- получать текущую игру;
- обновлять игру после хода;
- получать пользователя по UUID.

Если игра идет против компьютера, после хода пользователя компьютер делает ответный ход. Если игра идет между двумя пользователями, после хода одного игрока очередь переходит к другому.

Технологии

- Flask

Чему учит проект

Проект помогает разобраться, как устроен backend на Flask, как подключать базу данных через SQLAlchemy, как делать регистрацию и авторизацию, как защищать endpoint'ы, как хранить состояние игры и как разделять приложение на слои.

В результате должен получиться backend для крестиков-ноликов с базой данных, пользователями, авторизацией и поддержкой игры против компьютера или второго игрока.
