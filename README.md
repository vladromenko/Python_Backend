# Python Backend

Учебный backend-репозиторий на Python. Внутри два проекта, связанные между собой: оба развивают серверную часть игры в крестики-нолики, но делают упор на разные темы backend-разработки.

## Проект 1. Крестики-нолики с Basic Auth и PostgreSQL

Первый проект — backend для игры в крестики-нолики с базой данных, пользователями и базовой авторизацией.

В проекте реализуется переход от хранения данных в памяти к полноценной работе с PostgreSQL через SQLAlchemy. Пользователи, игры и состояние партий сохраняются в базе данных.

Основные возможности:

- регистрация пользователей;
- авторизация через Basic Auth;
- хранение пользователей и игр в PostgreSQL;
- создание новой игры;
- игра против компьютера;
- игра между двумя пользователями;
- подключение второго игрока к партии;
- получение списка доступных игр;
- получение текущего состояния игры;
- проверка корректности ходов;
- определение победы, ничьей или продолжения игры.

Приложение построено по слоям:

- `web` — HTTP-запросы, контроллеры и модели API;
- `domain` — бизнес-логика игры и пользователей;
- `datasource` — работа с базой данных;
- `di` — настройка зависимостей.

Этот проект помогает понять, как строится backend-приложение на Flask, как подключается база данных, как реализуются сервисы, репозитории, мапперы и защита endpoint'ов через логин и пароль.

## Проект 2. Крестики-нолики с JWT, историей игр и таблицей лидеров

Второй проект продолжает первый и заменяет Basic Auth на JWT-авторизацию.

Теперь после входа пользователь получает два токена:

- `accessToken` — используется для доступа к защищенным endpoint'ам;
- `refreshToken` — используется для обновления accessToken.

Защищенные запросы должны отправляться с заголовком:

`Authorization: Bearer accessToken`

Если токен отсутствует, истек или некорректен, сервер возвращает `401 Unauthorized`.

Дополнительно в проект добавляется история игр и таблица лидеров.

Основные возможности:

- авторизация через JWT;
- генерация accessToken и refreshToken;
- обновление accessToken;
- обновление refreshToken;
- получение пользователя по accessToken;
- защита endpoint'ов через Bearer-токен;
- хранение даты создания игры;
- получение завершенных игр пользователя;
- расчет таблицы лидеров;
- получение первых N лучших игроков.

Завершенной считается игра, которая закончилась победой одного из игроков или ничьей. В таблице лидеров для пользователей рассчитывается соотношение побед к поражениям и ничьим.
