Проект: Крестики-нолики с JWT-авторизацией

Это продолжение backend-приложения для игры в крестики-нолики. В этой версии basic-авторизация заменяется на JWT, добавляется история завершенных игр и таблица лидеров.

Приложение по-прежнему использует Flask, PostgreSQL и SQLAlchemy. Данные пользователей и игр хранятся в базе данных, а доступ к защищенным endpoint'ам выполняется через токены.

Что нужно реализовать

В проекте нужно заменить авторизацию по логину и паролю на JWT-авторизацию.

Пользователь отправляет логин и пароль, а сервер возвращает два токена:

- accessToken — короткоживущий токен для доступа к защищенным запросам;
- refreshToken — токен для обновления accessToken.

Для работы с токенами нужно создать JwtProvider. Он должен уметь создавать accessToken и refreshToken, проверять их валидность и получать UUID пользователя из токена.

В запросах к защищенным endpoint'ам клиент должен передавать accessToken в заголовке Authorization в формате:

Bearer accessToken

Если токен отсутствует, истек или некорректен, сервер должен вернуть 401 Unauthorized.

Также нужно добавить endpoint'ы для авторизации, обновления accessToken, обновления refreshToken и получения информации о пользователе по accessToken.

История игр

В модель игры нужно добавить дату создания.

Также нужно реализовать получение истории завершенных игр пользователя. Завершенной считается игра, которая закончилась победой одного из игроков или ничьей.

Пользователь должен иметь возможность получить список своих завершенных игр по accessToken. Этот endpoint должен быть доступен только авторизованным пользователям.

Таблица лидеров

Нужно добавить таблицу лидеров.

Для каждого пользователя нужно посчитать соотношение побед к проигрышам и ничьим. Затем нужно отсортировать игроков по этому показателю и вернуть первые N лучших игроков.

Endpoint таблицы лидеров должен принимать N — количество игроков, которое нужно вернуть.

В ответе должен быть список лучших игроков с их UUID, логином и соотношением побед.

Доступ к таблице лидеров должен быть только у авторизованных пользователей.

Основные возможности API

Приложение должно уметь:

- авторизовать пользователя через JWT;
- выдавать accessToken и refreshToken;
- обновлять accessToken;
- обновлять refreshToken;
- получать пользователя по accessToken;
- защищать endpoint'ы через Bearer-токен;
- получать историю завершенных игр пользователя;
- получать таблицу лидеров.

Чему учит проект

Проект помогает разобраться, как работает JWT-авторизация, чем accessToken отличается от refreshToken, как защищать API через Bearer-токен, как получать данные пользователя из токена, как хранить историю игр и как строить таблицу лидеров на основе данных из базы.

В результате должен получиться backend для крестиков-ноликов с JWT-авторизацией, историей игр и рейтингом лучших игроков.
